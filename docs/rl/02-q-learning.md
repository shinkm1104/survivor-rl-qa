## 1. 알고리즘

Q-learning은 **행동 가치 함수** Q(s, a)를 표(Q 테이블)에 직접 저장하고, 매 스텝 **시간차(TD) 학습**으로 갱신하는 **오프폴리시** 알고리즘이다. Q(s, a)는 "상태 s에서 행동 a를 하고 그 뒤로 가장 좋게 행동했을 때 기대되는 리턴(할인된 누적 보상)"이다.

```
TD 타깃 = r + γ · max_a' Q(s', a')        (사망으로 끝났으면 r만)
Q(s, a) ← Q(s, a) + α · (TD 타깃 − Q(s, a))
```

| 요소 | 이 프로젝트에서 | 코드 |
|---|---|---|
| 상태 s | 연속 관측 30개를 648개로 이산화 (가장 가까운 적 방향 8 × 거리 3 × 벽 근처 9 × 체력 3) | `survivor_rl/tabular.py` |
| 행동 a | 정지 + 8방향 이동, 9개 | `env.py` |
| 보상 r | 생존 스텝마다 +0.01, 사망 −1 | `env.py` |
| Q 테이블 | 마법사마다 648 × 9 = 5,832칸, 초기값 0 | `survivor_rl/qlearning.py` |
| 행동 정책(학습 중) | ε-탐욕: 확률 ε로 무작위 행동(탐험), 나머지는 Q값이 가장 큰 행동(활용) | `QLearner.act` |
| 목표 정책(평가) | 탐욕 정책: 항상 Q값이 가장 큰 행동 | `QPolicy` |
| 갱신 | 1-스텝 TD, 병렬 환경 16개의 전이를 매 스텝 한꺼번에 반영 | `QLearner.update` |

구현에서 신경 쓴 점:

- **종료와 시간 제한을 구분한다.** 사망은 진짜 종료(terminal)라 다음 상태 가치를 0으로 본다. 300초 도달은 학습 편의를 위한 시간 제한 절단(truncation)이라, 다음 상태 가치로 부트스트래핑을 계속한다. 이 구분이 없으면 에이전트는 300초 직전 상태를 사망만큼 나쁘게 배운다.
- **동점 처리.** 아직 갱신되지 않은 상태는 Q값이 모두 0이라, 그대로 두면 항상 0번 행동(정지)을 고른다. 아주 작은 난수를 더해 동점일 때는 무작위로 고른다.
- **오프폴리시.** 학습 중에는 ε-탐욕으로 움직이지만, TD 타깃은 다음 상태에서 가장 좋은 행동(max)으로 계산한다. 그래서 탐험 행동을 섞어 데이터를 모아도 탐욕 정책의 가치를 배운다.

## 2. 실험 설정

[1단계 설계](01-environment.md) 9절의 시작값을 그대로 썼다. 바꾼 것은 학습량 비교 실험(20,000 에피소드) 하나다.

| 하이퍼파라미터 | 값 |
|---|---|
| 학습률 α | 0.1 |
| 할인율 γ | 0.99 (유효 시야 약 100스텝 = 10초) |
| 탐험률 ε | 1.0 → 0.05, 전체 에피소드의 앞 50% 동안 선형 감소 |

| 병렬 환경 | Unity 프로세스 하나에 16개, 마법사 4명은 프로세스 4개로 동시에 |
| 학습 시드 | 0 \~ 899,999에서 무작위, 평가 시드(900,000 \~ 900,039)와 겹치지 않게 분리 |
| 레벨업 카드 | 규칙 기반 선택으로 고정 (학습 대상 아님, 4단계에서 학습) |

평가는 마법사당 평가 시드 40개로 하고, 탐험 없이 탐욕 정책으로 플레이한다. 지표는 평균 생존 시간과 **5분 생존율**(300초까지 살아남은 에피소드 비율)이다.

## 4. 분석

1. **학습은 된다.** 네 마법사 모두 Q-learning이 정지·무작위 봇보다 오래 살아남는다. 학습량을 10배로 늘리면 조금 더 오래 산다(마탄술사 137→161초, 바위술사 43→52초, 박수술사 35→54초).
2. **하지만 회피·사냥 봇에 크게 못 미친다.** 학습량을 10배 늘려 얻은 이득이 작고, 20,000 에피소드에서는 상태 대부분(595\~638개)을 이미 방문했다. 데이터가 모자라서가 아니라, 상태 표현이 담을 수 있는 정보가 모자란 것으로 본다.
   - 회피·사냥 봇은 주변 적 여러 마리의 위치와 경험치 구슬 위치를 쓴다. 표 기반 상태는 가장 가까운 적 한 마리만 본다.
   - 그래서 양쪽에서 적이 오는 상황과 한 마리만 오는 상황이 같은 상태가 되고(**상태 별칭**), 둘을 다르게 대처할 수 없다.
   - 경험치 구슬도 상태에 없으니 성장을 위해 일부러 움직이는 행동을 배우기 어렵다. 실제로 마탄술사에서 Q-learning은 회피·사냥 봇보다 레벨이 낮고(17.1 vs 21.9) 받은 피해가 많다(272 vs 167).
   - 이것은 가설이다. 3단계에서 같은 보상과 같은 평가로 관측 30개를 다 쓰는 DQN(함수 근사)을 학습해 확인한다.
3. **보상 설계는 원인으로 보지 않는다.** 에피소드 리턴은 `0.01 × 생존 스텝 − (사망 시 1)`이라 생존 시간과 순서가 같다. 회피·사냥 봇의 리턴이 Q-learning보다 높으므로, 보상은 더 좋은 정책을 제대로 더 높게 평가하고 있다. 다만 γ 0.99의 유효 시야는 약 10초라, 몇 분 뒤에 효과가 나는 성장(경험치 수집)은 학습 신호로 약하게 전달된다. DQN도 막히면 γ를 0.995나 0.999로 높여 본다.
4. **바위술사·박수술사는 회피·사냥 봇조차 5분 생존율이 2\~5%다.** 에이전트와 별개로 두 마법사가 약할 수 있다. 6단계 자동 QA에서 다룰 후보다.

## 5. 밸런스 이슈: 파동술사

### 5.1 발견: 가만히 있어도 이긴다

베이스라인 평가에서 파동술사는 정지 봇의 5분 생존율이 95%였다. 1단계 완료 기준("정지 봇 생존율이 높으면 학습 전에 밸런스부터 고친다")에 걸렸다. 이 상태에서는 Q-learning의 100%가 의미가 없다.

이 결과는 환경을 만들고 처음 돌린 평가에서 나온 **첫 자동 QA 발견**이다. 이전 버전의 984 에피소드 측정에서도 같은 유형("가만히 있어도 이기는 마법사")이 나왔고, 마법사 개편 뒤에도 남아 있었다.

### 5.2 검증: 30분 에피소드

5분이라 생긴 현상인지 보려고 에피소드 길이를 게임 최대치인 30분으로 늘려 다시 쟀다([`results/step2-pulse-30min`](../../results/step2-pulse-30min)).

| 봇 (30분) | 평균 생존 | 30분 생존율 | 받은 피해 평균 |
|---|---:|---:|---:|
| 정지 | 1,719초 | 95% | 86 |
| 도주 | 1,762초 | 98% | 45 |
| 회피·사냥 | 1,433초 | 78% | 196 |

- 정지 봇은 30분에서도 95%가 살아남는다. 받은 피해 평균이 5분 에피소드와 똑같이 86이다. 처음 5분을 넘기면 그 뒤로는 피해를 전혀 받지 않는다는 뜻이다.
- 에피소드 길이가 아니라 실제 밸런스 문제다. 파동술사는 자기 주위 원 안의 적을 전부 때리므로, 다가오는 적이 몸에 닿기 전에 맞는다. 화력이 적 생성 속도를 앞서면 아무도 닿지 못한다. (가설. 웨이브 강화는 270초에 끝나고 그 뒤로 더 세지지 않는다.)
- 오히려 움직이는 봇(회피·사냥)이 더 자주 죽는다. 이 마법사는 움직일 이유가 없었다.

### 5.3 수치 실험

빌드 폴더의 `balance.json`만 잠시 바꿔 베이스라인 봇을 다시 쟀다(평가 에피소드 40개, 5분).

| 공격 속도 ×0.8 | 215초 / 65% | 175초 / 48% | 211초 / 40% |
| 공격 속도 ×0.65 | 82초 / 18% | 61초 / 8% | 161초 / 13% |
| 피해 3.5 | 275초 / 90% | 180초 / 45% | 195초 / 30% |
| 피해 3.0 | 144초 / 40% | 106초 / 23% | 153초 / 13% |
| 반경 2.0 | 216초 / 68% | 126초 / 28% | 189초 / 30% |
| 반경 1.6 | 47초 / 3% | 48초 / 3% | 140초 / 8% |
| 반경 2.3, 공격 속도 ×0.9 | 216초 / 68% | 182초 / 50% | 198초 / 23% |
| 반경 2.2, 공격 속도 ×0.85 | 198초 / 60% | 113초 / 25% | 186초 / 28% |
| **반경 2.0, 공격 속도 ×0.8** | **51초 / 5%** | 40초 / 0% | **171초 / 22%** |
| 반경 2.0, 공격 속도 ×0.8, 피해 4.0 | 42초 / 3% | 37초 / 0% | 163초 / 18% |
| 반경 2.0, 공격 속도 ×0.8, 피해 3.5 | 27초 / 0% | 38초 / 3% | 134초 / 3% |

- 한 가지 수치만 낮추면 전체가 약해질 뿐, 정지 봇이 회피·사냥 봇보다 유리한 관계는 대체로 그대로다. 반경 1.6처럼 아주 약하게 만들어야 뒤집히는데, 그때는 회피·사냥 봇도 8%밖에 살아남지 못한다.
- 정지 봇은 적이 몸 주위로 모이게 둬서 한 번에 많이 잡고 빨리 성장한다(원래 값에서 처치 2,799 vs 1,255). 피해 다니면 파동 안에 들어오는 적이 줄어 성장이 늦다. 수치보다 구조(적이 모일수록 유리한 범위 공격)가 원인으로 보인다.
- 생존율이 문턱처럼 갈린다. 공격 속도 ×0.8과 ×0.65 사이, 반경 2.0과 1.6 사이에서 급히 떨어진다. 일정 레벨을 넘기면 위협이 사라지는 눈덩이 구조로 보인다. (가설. 카드 구성 분석으로 확인한다.)
- 반경과 공격 속도를 같이 낮추면 처음으로 정지 봇이 회피·사냥 봇보다 불리해진다. 피해까지 낮추면 회피·사냥 봇도 거의 살아남지 못한다.

### 5.4 결정 (2026-11-24)

반경 2.5→2.0, 공격 속도 ×0.8(초당 1.80→1.44회). 피해 4.4는 그대로 둔다. 결과는 3.1.

### 5.5 남은 문제: 도망이 싸움보다 낫다

- 수정 후 파동술사는 도주 봇(32%)이 회피·사냥 봇(22%)보다 5분 생존율이 높다. 평균 생존은 회피·사냥 봇이 더 길다(171초 vs 139초).
- 회피·사냥 봇의 처치 수가 1,255에서 86으로 줄었다. 싸워서 성장하기보다 피해서 버티는 마법사가 됐다. 이전 버전 측정의 "도망만 다니면 이긴다" 문제와 같은 성격이다.
- 카드 구성 분석(빌드 필요)과 함께 다음 밸런스 후보로 둔다.

## 6. 정정 기록

**마법사 이름 (2026-11-24).** 처음 기록할 때 Python의 마법사 이름 목록이 게임 순서와 달라 0번(파동술사)과 1번(마탄술사)이 뒤바뀌어 있었다. 이 문서와 `results/*/summary.md`의 표는 라벨만 고쳤고 수치는 그대로다. `games.csv`의 `class` 값은 게임 순서(0 파동술사, 1 마탄술사, 2 바위술사, 3 박수술사)를 따른다. 이전 버전의 공명술사가 지금의 파동술사이고, 그때도 웨이브 도입 뒤 정지 봇 87.5%로 같은 문제가 남아 있었다.
