## 1. 목표

- Python이 게임을 한 스텝씩 진행하고, 매 스텝 관측과 보상을 받는다.
- 화면을 그리지 않고 실제 시간보다 훨씬 빠르게, 여러 에피소드를 병렬로 돌린다.
- 학습 없이 규칙으로 움직이는 베이스라인 봇과 평가 루프를 먼저 만들어, 이후 알고리즘을 같은 기준으로 잰다.
- 학습 자체가 무의미해지는 밸런스 문제(가만히 있어도 이기는 등)가 있는지 여기서 걸러낸다.

## 2. 시스템 구조

```
Python (에이전트: 학습·평가)                 Unity (환경, 헤드리스 빌드)
┌───────────────────────────┐  로컬 TCP   ┌────────────────────────────────┐
│ survivor_rl/env.py (보상)  │ ◄─────────► │ RlServer (관측 30개, 행동 9개)  │
│ bots.py  qlearning.py     │ 관측 ↑ 행동 ↓ │   └ Simulation.Step(입력, 0.05) │
│ eval.py  train_q.py       │             │   한 프로세스에 환경 N개         │
└───────────────────────────┘             └────────────────────────────────┘
```

- **연결**: 직접 만든 로컬 TCP 연결(`Assets/Scripts/RL/RlServer.cs` ↔ `python/survivor_rl/env.py`).
  - 처음에는 ML-Agents를 쓰려 했으나 바꿨다. ML-Agents는 Python 버전 제약이 까다롭고(이 PC는 3.11) Unity 패키지를 따로 받아야 한다. 직접 만든 연결은 의존성이 numpy뿐이고, 한 Unity 프로세스에서 환경 N개를 묶어 한 번에 진행해 더 빠르다.
  - 5단계 PPO도 이 연결 위에서 PyTorch로 직접 구현한다.
- **헤드리스 실행**: 빌드한 실행 파일을 `SurvivorLab.exe -batchmode -nographics --rl-server --port=N`으로 띄운다. Python이 포트를 열고 Unity가 접속한다.
- **시뮬레이션**: 기존 `Simulation`을 그대로 쓴다. 렌더링과 분리돼 있고, 시드가 같으면 결과가 같다(결정론적). 실제 시간이 아니라 Python 요청이 올 때마다 고정 시간만큼 진행한다.
- **보상과 종료 판정**: 보상과 에피소드 종료(사망·시간 제한)는 Python(`env.py`)에서 정한다. 보상을 바꿀 때 Unity를 다시 빌드할 필요가 없다.
- **병렬 환경**: 한 프로세스에 환경 N개(학습 16개, 평가 40개). 마법사별 학습은 프로세스 4개를 동시에 띄운다.

### 통신 프로토콜

| 방향 | 명령 | 내용 |
|---|---|---|
| Python → Unity | `R` | 환경 수 N, 환경마다 (마법사, 시드). 시드 < 0이면 그 환경은 그대로 둠 |
| Python → Unity | `S` | 환경마다 행동 1바이트. 살아 있는 환경을 0.1초 진행 |
| Python → Unity | `Q` | 종료 |
| Unity → Python | (R·S 응답) | 환경마다 관측 30개 + 시간·처치 수·받은 피해·체력·레벨 + 사망 여부 |

레벨업 카드가 나오면 게임 시계가 멈추고 규칙 기반 선택기가 카드를 고른다. 이 호출은 틱으로 세지 않으므로, 한 스텝은 항상 게임 시간 0.1초다.

## 3. 에피소드

| 항목 | 값 | 비고 |
|---|---|---|
| 시뮬레이션 틱 | 0.05초 | 기존 `Simulation.Step` 고정값 |
| 스텝 (의사결정 주기) | 0.1초 = 2틱 | 기존 버전과 같음 |
| 학습 에피소드 길이 | **최대 300초(5분) = 3,000스텝** | 게임 규칙(최대 30분)은 그대로 두고 학습 설정에서만 자름 |
| 평가 에피소드 길이 | 최대 300초 | 에이전트가 5분을 안정적으로 버티면 30분으로 늘림 |
| 마법사 | 마법사마다 정책을 따로 학습 | 마법사 4명을 프로세스 4개로 동시에 |
| 레벨업 카드 선택 | 규칙 기반(`RuleRewardChooser`)으로 고정 | 4단계(REINFORCE)에서 학습 대상으로 바꿈 |

- 마지막 웨이브 강화가 270초에 들어오므로, 5분 에피소드로도 모든 웨이브를 겪는다.
- **사망은 종료(terminal), 300초 도달은 시간 제한 절단(truncation)이다.** 절단된 에피소드는 "그 뒤에도 살아 있었을 것"으로 보고, 다음 상태의 가치로 부트스트래핑을 계속한다. 이렇게 하지 않으면 에이전트가 300초 직전 상태를 사망만큼 나쁘게 배운다.

## 4. 관측과 상태

Unity는 연속값 벡터 하나를 관측으로 보낸다. 신경망 기반 알고리즘(DQN·PPO)은 이 관측을 그대로 쓰고, 표 기반 Q-learning은 Python에서 이산 상태로 바꿔 쓴다.

**연속 관측 (DQN·PPO용)**

| 값 | 개수 | 정규화 |
|---|---:|---|
| 가까운 적 8마리의 상대 위치 (x, y) | 16 | 경기장 반폭(32)으로 나눔. 없으면 0 |
| 가까운 적 8마리의 빠른 적 여부 | 8 | 0/1 |
| 플레이어 위치 (x, y) | 2 | 경기장 반폭으로 나눔 |
| 체력 비율 | 1 | 0 \~ 1 |
| 가장 가까운 경험치 구슬의 상대 위치 | 2 | 경기장 반폭으로 나눔 |
| 경과 시간 | 1 | 300초로 나눔 |
| **합계** | **30** | |

**이산 상태 (표 기반 Q-learning용, 기존 버전 구성 유지)**

| 값 | 구간 | 개수 |
|---|---|---:|
| 가장 가까운 적의 방향 | 8방향 | 8 |
| 가장 가까운 적의 거리 | 가까움 / 중간 / 멂 | 3 |
| 벽 근처 | x축(왼쪽·없음·오른쪽) × y축(아래·없음·위) | 9 |
| 체력 | 낮음 / 중간 / 높음 | 3 |
| **상태 공간 크기** | | **648** |

구간 경계값(`python/survivor_rl/tabular.py`): 거리는 3 미만 가까움 / 7 미만 중간 / 그 이상 멂(적이 없으면 멂). 7은 기존 회피 봇이 위협으로 보는 반경이다. 벽은 벽에서 6 이내, 체력은 1/3·2/3 기준이다. 봇 플레이 분포를 보고 정한 값은 아니다.

## 5. 행동

- 이산 행동 공간 9개: 정지 + 8방향 이동
- 공격은 게임 규칙대로 자동

## 6. 보상

| 사건 | 보상 |
|---|---:|
| 살아 있는 스텝마다 | **+0.01** |
| 사망 | **−1** (에피소드 종료) |
| 처치·피격 | 없음 |

- 에피소드 리턴은 `0.01 × 생존 스텝 − (사망 시 1)`이라, 오래 살아남는 정책일수록 리턴이 크다. 평가 지표(생존 시간)와 순서가 같다.
- 사망 −1은 생존 100스텝(10초) 분량이다. 할인율 0.99의 유효 시야도 약 100스텝이라 두 값의 범위가 맞는다.
- 보상 크기를 ±1 안쪽으로 둔 것은 3단계 이후 신경망 학습을 안정시키기 위해서다. 2\~7단계 모두 이 보상을 그대로 쓴다.
- 처치·피격 같은 보상 셰이핑은 넣지 않는다. 성장이 생존에 도움이 되면 에이전트가 스스로 배워야 한다. 학습이 막히면 그때 작게 추가하고, 바꾼 내용을 이 문서에 남긴다.

## 7. 베이스라인 봇

학습 없이 규칙으로만 움직이는 기준 정책이다. 학습한 에이전트는 최소한 이 봇들보다 나아야 한다.

| 봇 | 동작 | 확인하는 것 |
|---|---|---|
| 정지 봇 | 움직이지 않음 | 가만히 있어도 이기는지 |
| 무작위 봇 | 9개 행동 중 무작위 | 최저 기준 |
| 도주 봇 | 가장 가까운 적의 반대 방향으로 이동 | 도망만 다녀도 사는지 |
| 회피·사냥 봇 | 적이 가까우면 피하고, 멀면 경험치 구슬로 이동 (기존 버전의 kite 봇을 옮김) | 사람이 설계한 괜찮은 플레이 수준 |

## 8. 평가 프로토콜

| 항목 | 값 |
|---|---|
| 학습 시드 | 0 \~ 899,999 |
| 평가 시드 | 900,000 \~ 900,039 (마법사당 40개, 기존 버전과 같음) |
| 평가 대상 | 베이스라인 봇 4개 + 학습한 에이전트, 마법사 4명 |
| 지표 | 평균 생존 시간, 생존 시간 중앙값, 5분 생존율, 처치 수, 받은 피해 |
| 결과 저장 | `results/<단계>-<내용>/` 아래 `games.csv`(에피소드별), `summary.csv`, `summary.md`(요약 표) |

- 평가 중에는 탐험 없이 탐욕 정책(가장 Q값이 큰 행동)으로만 플레이한다.
- 학습 시드와 평가 시드를 분리해, 평가 맵에 과적합된 정책이 좋게 나오지 않게 한다.
- 실패한 에피소드를 `마법사 + 시드`로 다시 재생해 화면으로 확인하는 기능은 아직 없다(6단계 자동 QA에서 추가).

## 9. 알고리즘별 하이퍼파라미터 시작값

각 단계를 시작할 때의 출발점이다. 실제로 쓴 값과 바꾼 이유는 해당 단계 문서에 남긴다.

**공통**

| 항목 | 값 |
|---|---|
| 할인율 γ | 0.99 |
| 스텝 | 0.1초 |
| 에피소드 길이 | 최대 300초 (3,000스텝) |
| 보상 | 생존 +0.01/스텝, 사망 −1 |

**2단계 표 기반 Q-learning (이동)**

| 항목 | 시작값 | 기존 버전 |
|---|---|---|
| 학습률 α | 0.1 | 0.14 |
| 할인율 γ | 0.99 | 0.98 |
| 탐험률 ε | 1.0 → 0.05, 전체 학습의 앞 50% 동안 선형 감소 | 0.85 → 0.06 |
| 학습량 | 마법사당 2,000 에피소드 | |
| Q 초기값 | 0 | |

**3단계 DQN (이동)**

| 항목 | 시작값 |
|---|---|
| Q 네트워크 | 은닉층 2개 × 128, ReLU |
| 옵티마이저 | Adam, 학습률 1e-4 |
| 손실 함수 | Huber |
| 리플레이 버퍼 | 전이(transition) 100,000개 |
| 미니배치 크기 | 64 |
| 학습 시작 | 전이 1,000개가 쌓인 뒤 |
| 타깃 네트워크 갱신 | 1,000스텝마다 |
| 탐험률 ε | 1.0 → 0.05, 앞 100,000스텝 동안 선형 감소 |
| 총 학습량 | 마법사당 1,000,000스텝 |

**4단계 REINFORCE (레벨업 카드 선택)**

| 항목 | 시작값 |
|---|---|
| 행동 | 제시된 카드 3장 중 1장 |
| 관측 | 현재 보유 카드·레벨·체력 비율·경과 시간 |
| 정책 네트워크 | 은닉층 2개 × 64 |
| 옵티마이저 | Adam, 학습률 1e-3 |
| 베이스라인 | 최근 에피소드 리턴의 이동 평균 |
| 이동 정책 | 3단계에서 학습한 DQN으로 고정 |

**5단계 PPO (PyTorch 직접 구현, 이동 + 카드 선택)**

| 항목 | 시작값 |
|---|---|
| 학습률 | 3e-4 (선형 감소) |
| 미니배치 / 롤아웃 버퍼 크기 | 1,024 / 10,240 |
| 에폭 수 | 3 |
| 클리핑 ε | 0.2 |
| GAE λ | 0.95 |
| 엔트로피 계수 β | 5e-3 |
| 롤아웃 길이 | 64스텝 |
| 정책·가치 네트워크 | 은닉층 2개 × 128 |
| 총 학습량 | 마법사당 2,000,000스텝 |

### 값을 고른 이유

근거는 세 가지다: 기존 버전 값, 널리 쓰이는 기본값, 이 프로젝트에 맞춘 판단. 판단으로 정한 값은 측정 후 조정한다.

| 항목 | 이유 |
|---|---|
| 스텝 0.1초 | 기존 버전과 같음. 플레이어 속도 5 기준 한 스텝에 0.5칸 이동이라 피하기에 충분히 잦다. 더 짧으면 에피소드당 스텝이 늘어 어떤 행동이 좋았는지 배우기 어려워진다(신용 할당 문제) |
| 에피소드 길이 5분 | 마지막 웨이브 강화가 270초라 5분이면 모든 웨이브를 겪음 |
| 연속 관측 30개 | 신경망은 입력 크기가 고정돼야 해서 가까운 적 8마리로 제한. 빠른 적(2.1배 속도)은 위험도가 달라 따로 표시, 위치는 벽 판단, 구슬은 성장, 시간은 웨이브 강도. 모두 −1 \~ 1로 정규화 |
| 이산 상태 648개 | 기존 구성. 648 × 9행동 = 5,832칸, 2,000 에피소드 × 3,000스텝이면 칸당 평균 약 1,000번 방문. 더 크면 방문하지 못하는 칸이 생김 |
| 행동 9개 | 기존과 같음. 게임 조작이 8방향이고 Q-learning·DQN은 이산 행동 공간이 필요 |
| 보상 +0.01 / −1 | 사망 = 생존 100스텝(10초) 분량. 비율은 +1 / −100과 같지만 신경망 학습 안정을 위해 ±1 안쪽 크기 |
| γ 0.99 | 유효 시야 약 100스텝(10초)으로 사망 벌점 범위와 맞음. 기존 0.98은 5초라 웨이브가 몰려오는 상황엔 짧음 |
| 평가 40개 | 기존과 비교 가능. 생존율 50% 근처에서 표준오차 약 ±8%p라 그보다 작은 차이는 우연일 수 있음 |
| 베이스라인 봇 4개 | 정지·도주 봇은 기존에 찾은 정지 승리·도주 승리 문제를 다시 확인, 무작위는 최저 기준, 회피·사냥은 사람이 설계한 괜찮은 플레이 |
| Q-learning | α 0.1은 교과서 기본값(기존 0.14와 비슷). 2,000 에피소드는 위 방문 수 계산 |
| DQN | 학습률·Huber 손실·타깃 네트워크는 DQN 논문과 주요 라이브러리 기본값 근처. 버퍼 100k는 약 33 에피소드 분량, 입력 30개라 2×128이면 충분 |
| REINFORCE | 카드 선택은 한 에피소드에 수십 번뿐이라 학습률을 크게(1e-3), 네트워크는 작게(2×64). 그래디언트 분산이 큰 방법이라 이동 평균 베이스라인으로 줄임 |
| PPO | 클리핑 0.2·λ 0.95는 PPO 논문 값, 3e-4·엔트로피 5e-3은 ML-Agents 예제에서 흔한 값 |

**알려진 빈틈**: 줄지어 맵을 쓸고 지나가는 유령 줄(line event)은 관측에 따로 없다. 가까운 8마리 안에 들어오면 보이지만, 멀리서 오는 줄은 미리 보지 못한다. 평가에서 이걸로 많이 죽으면 관측에 추가한다.
