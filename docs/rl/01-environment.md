# 1단계 설계: RL 환경

> Python에서 학습하고 Unity는 환경만 맡는다. 게임은 화면 없이(헤드리스) 빠르게 돌리고, 관측·행동·보상·평가 기준을 여기서 고정해 2~7단계가 같은 조건에서 비교되게 한다.

## 1. 목표

- Python 코드가 게임을 한 step씩 진행하고 관측·보상을 받는다.
- 화면을 그리지 않고 실제 시간보다 훨씬 빠르게 여러 판을 돌린다.
- 학습 없이 동작하는 비교용 봇과 평가 루프를 먼저 만들어, 이후 알고리즘의 성능을 같은 기준으로 잰다.
- 학습이 불가능할 정도의 밸런스 문제(가만히 있어도 이김 등)가 있는지 여기서 걸러낸다.

## 2. 구조

```
Python (학습·평가)                          Unity (환경, 헤드리스 빌드)
┌───────────────────────────┐  로컬 TCP   ┌────────────────────────────────┐
│ survivor_rl/env.py (보상)  │ ◄─────────► │ RlServer (관측 30개, 행동 9개)  │
│ bots.py  qlearning.py     │ 관측 ↑ 행동 ↓ │   └ Simulation.Step(입력, 0.05) │
│ eval.py  train_q.py       │             │   한 프로세스에 게임 N판         │
└───────────────────────────┘             └────────────────────────────────┘
```

- 연결: **직접 만든 로컬 TCP 연결** (`Assets/Scripts/RL/RlServer.cs` ↔ `python/survivor_rl/env.py`).
  - 처음에는 ML-Agents를 쓰려 했으나 바꿨다. ML-Agents는 Python 버전 제한이 까다롭고(이 PC는 3.11) Unity 패키지를 따로 받아야 한다. 직접 만든 연결은 의존성이 numpy뿐이고, 한 Unity 프로세스에서 게임 N판을 묶어 한 번에 진행해 더 빠르다.
  - PPO도 이 연결 위에서 PyTorch로 직접 구현한다.
- 헤드리스: 빌드한 실행 파일을 `SurvivorLab.exe -batchmode -nographics --rl-server --port=N`으로 띄운다. Python이 포트를 열고 Unity가 접속한다.
- 게임 로직: 기존 `Simulation`을 그대로 쓴다. 렌더링과 분리돼 있고 시드가 같으면 결과가 같다(결정론). 실제 시간이 아니라 Python 요청이 올 때마다 고정 시간만큼 진행한다.
- 보상과 판 종료(사망·시간 제한)는 Python(`env.py`)에서 정한다. 보상을 바꿀 때 Unity를 다시 빌드할 필요가 없다.
- 병렬: 한 프로세스에 게임 N판(학습 16판, 평가 40판), 마법사별 학습은 프로세스 4개를 동시에 띄운다.

### 통신 형식

| 방향 | 명령 | 내용 |
|---|---|---|
| Python → Unity | `R` | 판 수 N, 판마다 (마법사, 시드). 시드 < 0이면 그 판은 그대로 둠 |
| Python → Unity | `S` | 판마다 행동 1바이트. 살아 있는 판을 0.1초 진행 |
| Python → Unity | `Q` | 종료 |
| Unity → Python | (R·S 응답) | 판마다 관측 30개 + 시간·처치·받은 피해·체력·레벨 + 사망 여부 |

레벨업 카드가 나오면 게임 시계가 멈추고 규칙 기반 선택이 고른다. 이 호출은 2틱에 세지 않으므로, 한 번의 판단은 항상 게임 시간 0.1초다.

## 3. 한 판(에피소드)

| 항목 | 값 | 비고 |
|---|---|---|
| 게임 내부 시간 간격 | 0.05초 | 기존 `Simulation.Step` 고정값 |
| 판단 주기 | 0.1초 (게임 2틱) | 기존 버전과 같음 |
| 학습용 판 길이 | **300초(5분) = 3,000 step** | 게임 규칙(최대 30분)은 그대로 두고 학습 설정에서만 자름 |
| 평가용 판 길이 | 300초 | 30분은 에이전트가 5분을 안정적으로 버틸 때 늘림 |
| 마법사 | 한 번의 학습에 1명 고정 | 마탄술사부터. 4명 각각 따로 학습 |
| 레벨업 카드 선택 | 규칙 기반(`RuleRewardChooser`) 고정 | 4단계(REINFORCE)에서 학습 대상으로 바꿈 |

- 웨이브는 270초에 마지막 강화가 들어오므로, 5분 판으로도 모든 웨이브를 겪는다.
- **사망**은 진짜 종료(terminal)이고, **300초 도달**은 시간 제한에 의한 중단(truncation)이다. 시간 제한으로 끝난 판은 "그 뒤에도 살아 있었을 것"으로 보고 가치를 이어서 계산한다. 이렇게 하지 않으면 에이전트가 300초 직전을 사망과 같이 나쁘게 배운다.

## 4. 관측

Unity는 연속값 벡터 하나를 보낸다. 표 기반 Q-learning은 Python 쪽에서 이 값을 구간으로 나눠 쓴다.

**연속 관측 (DQN·PPO용)**

| 값 | 개수 | 정규화 |
|---|---:|---|
| 가까운 적 8마리의 상대 위치 (x, y) | 16 | 경기장 반폭(32)으로 나눔. 없으면 0 |
| 가까운 적 8마리의 빠른 적 여부 | 8 | 0/1 |
| 플레이어 위치 (x, y) | 2 | 경기장 반폭으로 나눔 |
| 체력 비율 | 1 | 0~1 |
| 가장 가까운 경험치 구슬의 상대 위치 | 2 | 경기장 반폭으로 나눔 |
| 경과 시간 | 1 | 300초로 나눔 |
| **합계** | **30** | |

**표 기반 관측 (Q-learning용, 기존 버전 구성 유지)**

| 값 | 구간 | 개수 |
|---|---|---:|
| 가장 가까운 적의 방향 | 8방향 | 8 |
| 가장 가까운 적의 거리 | 가까움 / 중간 / 멂 | 3 |
| 벽 근처 | x축(왼쪽·없음·오른쪽) × y축(아래·없음·위) | 9 |
| 체력 | 낮음 / 중간 / 높음 | 3 |
| **상태 수** | | **648** |

구간 경계값(2단계에서 정함, `python/survivor_rl/tabular.py`): 거리는 3 미만 가까움 / 7 미만 중간 / 그 이상 멂(적이 없으면 멂). 7은 기존 회피 봇이 위협으로 보는 반경이다. 벽은 벽에서 6 이내, 체력은 1/3·2/3 기준. 봇 플레이 분포를 보고 정한 값은 아니다.

## 5. 행동

- 이산 행동 9개: 정지 + 8방향 이동
- 공격은 게임 규칙대로 자동

## 6. 보상

| 사건 | 보상 |
|---|---:|
| 살아 있는 step마다 | **+0.01** |
| 사망 | **−1** (판 종료) |
| 처치·피격 | 없음 |

- 사망 −1은 생존 100 step(10초)치다. 할인율 0.99면 에이전트가 대략 100 step 앞까지 내다보므로 두 값의 범위가 맞는다.
- 보상 크기를 ±1 안쪽으로 둔 것은 3단계 이후 신경망 학습을 안정시키기 위해서다. 2~7단계 모두 이 보상을 그대로 쓴다.
- 학습이 안 되면 그때 처치·피격 보상을 작게 추가하고, 바꾼 내용을 이 문서에 남긴다.

## 7. 비교용 봇

학습 없이 규칙으로만 움직이는 기준선이다. 학습한 에이전트는 최소한 이 봇들보다 나아야 한다.

| 봇 | 동작 | 확인하는 것 |
|---|---|---|
| 정지 봇 | 움직이지 않음 | 가만히 있어도 이기는지 |
| 무작위 봇 | 9개 행동 중 무작위 | 최저 기준선 |
| 도주 봇 | 가장 가까운 적의 반대 방향 | 도망만 다녀도 사는지 |
| 회피·사냥 봇 | 적이 가까우면 피하고, 멀면 경험치 구슬로 이동 | 사람이 짠 괜찮은 플레이 수준 |

기존 버전(`unity-survivor-old`)의 봇이 있으면 동작을 맞춰 옮긴다.

## 8. 평가 루프

| 항목 | 값 |
|---|---|
| 훈련 시드 | 0 ~ 899,999 |
| 평가 시드 | 900,000 ~ 900,039 (마법사당 40판, 기존 버전과 같음) |
| 평가 대상 | 봇 4개 + 학습한 에이전트, 마법사 4명 |
| 지표 | 평균 생존 시간, 생존 시간 중앙값, 5분 완주율, 처치 수, 받은 피해 |

- 평가 중에는 탐색 없이 가장 좋은 행동만 고른다.
- 실패한 판은 `클래스 + 시드`로 다시 돌려 화면으로 확인할 수 있게 한다(기존 `--replay` 방식).

## 9. 알고리즘별 시작 설정

각 단계를 시작할 때의 출발점이다. 실제로 쓴 값과 바꾼 이유는 해당 단계 문서에 남긴다.

**공통**

| 항목 | 값 |
|---|---|
| 할인율 γ | 0.99 |
| 판단 주기 | 0.1초 |
| 판 길이 | 300초 (3,000 step) |
| 보상 | 생존 +0.01/step, 사망 −1 |

**2단계 표 기반 Q-learning (이동)**

| 항목 | 시작값 | 기존 버전 |
|---|---|---|
| 학습률 α | 0.1 | 0.14 |
| 할인율 γ | 0.99 | 0.98 |
| 탐색률 ε | 1.0 → 0.05, 전체 학습의 앞 50% 동안 선형 감소 | 0.85 → 0.06 |
| 학습 판 수 | 마법사당 2,000판 | |
| Q 초기값 | 0 | |

**3단계 DQN (이동)**

| 항목 | 시작값 |
|---|---|
| 신경망 | 은닉층 2개 × 128, ReLU |
| 최적화 | Adam, 학습률 1e-4 |
| 손실 | Huber |
| 리플레이 버퍼 | 100,000 transition |
| 배치 크기 | 64 |
| 학습 시작 | 1,000 step 쌓인 뒤 |
| 타깃 네트워크 갱신 | 1,000 step마다 |
| 탐색률 ε | 1.0 → 0.05, 앞 100,000 step 동안 선형 감소 |
| 총 학습량 | 마법사당 1,000,000 step |

**4단계 REINFORCE (레벨업 카드 선택)**

| 항목 | 시작값 |
|---|---|
| 행동 | 제시된 카드 3장 중 1장 |
| 관측 | 현재 보유 카드·레벨·체력 비율·경과 시간 |
| 신경망 | 은닉층 2개 × 64 |
| 최적화 | Adam, 학습률 1e-3 |
| 기준선(baseline) | 최근 판 수익의 이동 평균 |
| 이동 정책 | 3단계에서 학습한 DQN으로 고정 |

**5단계 PPO (PyTorch 직접 구현, 이동 + 카드 선택)**

| 항목 | 시작값 |
|---|---|
| 학습률 | 3e-4 (선형 감소) |
| batch_size / buffer_size | 1,024 / 10,240 |
| num_epoch | 3 |
| clip ε | 0.2 |
| GAE λ | 0.95 |
| 엔트로피 계수 β | 5e-3 |
| time_horizon | 64 |
| 신경망 | 은닉층 2개 × 128 |
| 총 학습량 | 마법사당 2,000,000 step |

### 값을 고른 이유

출처는 세 가지다: 기존 버전 값, 흔히 쓰는 출발값, 이 프로젝트에 맞춘 판단. 판단으로 정한 값은 1단계 측정 후 조정한다.

| 항목 | 이유 |
|---|---|
| 판단 주기 0.1초 | 기존 버전과 같음. 플레이어 속도 5 기준 한 판단에 0.5칸 이동이라 피하기엔 충분히 잦고, 더 짧으면 판당 step이 늘어 어떤 행동이 좋았는지 배우기 어려워짐 |
| 판 길이 5분 | 마지막 웨이브 강화가 270초라 5분이면 모든 웨이브를 겪음 |
| 연속 관측 30개 | 신경망은 입력 크기가 고정돼야 해서 가까운 적 8마리로 제한. 빠른 적(2.1배 속도)은 위험도가 달라 따로 표시, 위치는 벽 판단, 구슬은 레벨업, 시간은 웨이브 강도. 모두 −1~1로 맞춤 |
| 표 기반 648상태 | 기존 구성. 648 × 9행동 = 5,832칸, 2,000판 × 3,000 step이면 칸당 평균 약 1,000번 방문. 더 크면 방문 못 하는 칸이 생김 |
| 행동 9개 | 기존과 같음. 게임 조작이 8방향이고 Q-learning·DQN은 이산 행동이 필요 |
| 보상 +0.01 / −1 | 사망 = 생존 100 step(10초)치. 비율은 +1 / −100과 같지만 신경망 학습 안정을 위해 ±1 안쪽 크기 |
| γ 0.99 | 약 100 step(10초) 앞을 내다봐 사망 벌점 범위와 맞음. 기존 0.98은 5초라 웨이브가 몰려오는 상황엔 짧음 |
| 평가 40판 | 기존과 비교 가능. 완주율 50%에서 오차 약 ±8%p라 그보다 작은 차이는 우연일 수 있음 |
| 비교용 봇 4개 | 정지·도주 봇은 기존에 찾은 정지 승리·도주 승리 재확인, 무작위는 최저선, 회피·사냥은 사람이 짠 괜찮은 플레이 |
| Q-learning | α 0.1은 교과서 기본값(기존 0.14와 비슷). 2,000판은 위 방문 수 계산 |
| DQN | 학습률·Huber·타깃 네트워크는 DQN 논문과 주요 라이브러리 기본값 근처. 버퍼 100k는 약 33판 분량, 입력 30개라 2×128이면 충분 |
| REINFORCE | 카드 선택은 한 판에 수십 번뿐이라 학습률을 크게(1e-3), 신경망은 작게(2×64). 분산이 큰 방법이라 이동 평균 기준선으로 줄임 |
| PPO | clip 0.2·λ 0.95는 PPO 논문 값, 3e-4·엔트로피 5e-3은 ML-Agents 예제에서 흔한 값 |

알려진 빈틈: 줄지어 쓸고 지나가는 유령 줄(line event)은 관측에 따로 없다. 가까운 8마리 안에 들어오면 보이지만 멀리서 오는 줄은 미리 못 본다. 봇 평가에서 이걸로 많이 죽으면 관측에 추가한다.

```
Assets/Scripts/RL/RlServer.cs   관측·행동, 헤드리스 서버
python/
  survivor_rl/env.py            Unity 연결, 보상·판 종료, 여러 판 동시 진행
  survivor_rl/features.py       관측 읽기 도우미
  survivor_rl/bots.py           비교용 봇 4개

  survivor_rl/qlearning.py      2단계 Q-learning

results/                        평가·학습 결과
```
